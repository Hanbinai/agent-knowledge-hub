# 可选渐进式入门（3.7.0）

这不是职业测评，也不是必填个人档案。任何职业、学生、退休、多角色、不愿透露职业或目标未定的用户都可以使用；不套用任何安装者的个人资料。

## 用户如何开始

连接 Hub 后，可以说“开始引导”，也可以直接做任务。没有客户端主动触发或自动弹窗：消费 Agent 需要读取 `get_context`、`start_project_session` 或 `get_onboarding` 才能看到 readiness 与引导契约。已有当前身份可读的有效确认偏好时，不主动要求重做；仍可由用户主动开始。

Agent 先说明能力和隐私边界，再询问是否愿意开始。每轮只问 1–2 个问题，围绕当下目的、具体场景、成功标准、困难、希望 AI 如何配合，按本轮回答调整后续问题，而非按职业关键词套问卷。职业不是必答项；目标没想好也可以先找一件小事。

随时可以说“纠正刚才的回答”“跳过这题”“暂停”“跳过整个引导”“完成”“恢复引导”，或“只在当前对话使用，不保存”。完成不要求保存任何偏好。恢复时只知道进度，不知道之前的回答；Agent 应说明这一点，而不是假装记得。只有用户主动恢复，才继续暂停、跳过或已完成的引导。

## 能力与隐私边界（提问前解释）

- Hub 是本地记忆与跨 Agent 交接工具，不保证任务结果，也不会自动替用户执行所有事情。Agent 可能误解或犯错。
- 原始回答默认留在当前对话，不自动写入 Inbox、work、Self、`.state` 或会话总结。客户端聊天本身如何保存由客户端决定。
- 对话回答及读取的资料会进入客户端所用模型的上下文，适用该客户端和模型服务商的隐私政策；“本地 Hub”不等于对话从不出网。
- 同一系统账户可访问的本地文件不是加密保险箱；MCP 权限控制不能代替文件加密。
- 引导不启用、不读取、不写入 Self，也不改变身份或权限。Self 必须另行显式授权，不能把同意引导当作授权。

## 给消费 Agent 的调用协议

`get_onboarding()` 为只读操作。自然入口返回同样的 `onboarding` 字段，包含 `status`、`revision`、`should_invite`、`readiness` 和 `contract`。读取不会创建入门状态。

`update_onboarding(action, expected_revision, user_confirmed=false)` 只接受固定动作，不接受回答、职业、自由文本、调用方身份或权限设置。

| 动作 | 合法来源 | 目标 | 用户确认 |
|---|---|---|---|
| invite | not_started 且无当前可读有效偏好 | invited | 不需要，仅标记一次邀请 |
| start | not_started / invited | active | 必须 |
| pause | active | paused | 必须 |
| skip | not_started / invited / active / paused | skipped | 必须 |
| complete | active | completed | 必须 |
| resume | paused / skipped / completed / invited | active | 必须 |

先读取修订号。主动邀请前先原子调用 invite，只有 `idempotent_replay=false` 的获胜调用方展示邀请；重放不再邀请。进程在标记后崩溃可能漏显示一次邀请，这是避免重复打扰的保守选择，用户仍可说“开始引导”。其余动作只在用户明确同意该动作后调用。字段中的确认是 Agent 对用户授权的声明，不是能够技术验证人类同意的证明。

状态按 MCP 进程绑定的 Agent 身份隔离，不是多自然人账户体系。同一 Hub 原则上属于同一用户；多自然人应使用独立 Hub/系统账户。不同 Agent 不共享入门进度，且不会通过入门接口看到其他身份的偏好。现有共享偏好会在各获授权 Agent 处抑制邀请。若不允许持久化任何进度，整个引导只在当前会话进行，不调用写工具；跨会话不重复邀请无法在完全不存状态的前提下保证。

只持久化 `status`、递增 `revision`、`last_action` 到 `.state/onboarding/<身份SHA256>.json`。复用 `FileLock` 与原子写入，拒绝非法状态和陈旧修订；仅允许对最近同一操作的精确重试。禁止自动重置损坏状态。不会读取 Self 或改写 AGENTS.json。

## 可选确认偏好

Agent 可以在对话中提出简短候选，但未经同意不能落盘。必须分别确认“准确内容”与“具体接收 Agent”，然后复用 `record_user_preference`，同时设 `user_confirmed=true`、`sharing_confirmed=true` 并给出明确 `share_with_agents`。不能默认全体共享，不能把回答原文或诊断复制成工作偏好。更新/纠正已存偏好遵循 `expected_record_id` 机制，停用用 `active=false`。新安装没有登记身份时，先按既有权限管理流程明确登记 work-only 身份；引导不会自动登记或提权。

## 完全虚构的对话示例

以下均为虚构场景，不来自安装者资料，且不作为程序分支。

- 学生：“我想把复习安排得轻松一点。”Agent：“这周最想完成哪一件事？怎样算安排对你有帮助？”
- 退休用户：“我想整理旅行照片。”Agent：“想先整理哪一批？你更希望我给步骤，还是先一起挑分类方式？”
- 多角色用户：“白天做实验，周末组织读书会。”Agent：“今天先帮哪一个场景？现在最卡在哪里？”
- 不透露职业：“不想说工作，只想理清一件事。”Agent：“可以不说。你希望聊完后，哪一点变得更清楚？”
- 目标未定：“还不知道能用来做什么。”Agent：“最近有没有一件想少花精力的小事？也可以先看一个不保存资料的小示例。”

这些回答都留在对话。是否保存合作方式由用户另外决定，任何问题都可以跳过。
